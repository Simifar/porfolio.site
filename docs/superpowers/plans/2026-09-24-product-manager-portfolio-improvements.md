# Product Manager Portfolio Improvement Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать портфолио понятной презентацией Product Manager для рекрутера и нанимающего менеджера: быстро объяснять профиль, показывать проверяемые кейсы и вести к резюме или контакту.

**Architecture:** Сохранить одностраничное React/Vite-приложение с HashRouter, двуязычными данными и статической публикацией на GitHub Pages. Перестроить смысл и иерархию главной, карточки и страницы проектов; использовать только реальные материалы и подтверждённые сведения.

**Tech Stack:** React 18, TypeScript 5.7, Vite 6, React Router 6, Tailwind CSS 4, Framer Motion 11.

**Spec:** Отдельная дизайн-спецификация не утверждалась. План основан на запросе пользователя, подтверждённой цели поиска работы Product Manager и аудите текущей рабочей версии.

## Global Constraints

- Сохранить версии и стек из `package.json`; отдельного тестового скрипта в проекте нет.
- Сохранить HashRouter и базовый путь GitHub Pages `/porfolio.site/`.
- Оставить русский и английский варианты интерфейса; основной рынок и язык по умолчанию ещё нужно определить.
- Не добавлять неподтверждённые метрики, отзывы, результаты, опыт, должности или названия клиентов.
- Не изображать отсутствующий опубликованный продукт как действующий сайт; для него показывать репозиторий и реальные материалы.
- Не менять публикацию и не отправлять изменения во внешние сервисы в рамках реализации плана без отдельного запроса.

## Review Focus

- Русские заголовки и длинные подписи при ширине 320 px должны переноситься без обрезания и горизонтальной прокрутки; проверить главную и страницы кейсов.
- Проекты без опубликованного сайта должны вести в кейс или репозиторий и не показывать действие «Открыть сайт»; проверить карточки TaskFocus и Telegram Growth Analytics.
- Если для проекта нет подтверждённого результата или метрики, кейс должен описывать статус и сделанные решения без выдуманного результата; проверить все четыре проекта.
- Если скриншот проекта отсутствует или не загружается, карточка и кейс должны сохранять рабочую иерархию и понятные ссылки; проверить проекты с изображением и без него.
- Прямое открытие и обновление `/#/work/<slug>` в сборке GitHub Pages должно сохранять нужный кейс и его ресурсы; проверить каждый slug после сборки.

## Audit Findings

### P0 — Позиционирование не помогает оценить кандидата

- Первый экран занимает почти весь экран крупным «Product Manager / который создаёт», но поддерживающий текст повторяет широкие формулировки про продукт, координацию и разработку. Не видны целевой профиль, домен, уровень, конкретная специализация или резюме.
- Декоративный граф «Idea—Research—Build—Ship» занимает значительную часть desktop-экрана, но не показывает вклад Егора или результаты работы. На мобильном он скрыт.
- Текст в блоках Statement и About объясняет устройство портфолио и оговаривается об отсутствии неподтверждённых метрик. Это честно, но занимает место, которое нужно для конкретной профессиональной истории.

### P1 — Работы трудно рассмотреть

- Карточки на главной не используют уже имеющиеся скриншоты CortexMap и MindTrack. Визуально они выглядят как большие однотонные блоки; первая карточка растянута на две колонки. Для TaskFocus и Telegram Growth Analytics в данных скриншотов нет.
- Подпись «Открыть сайт» у CortexMap и MindTrack находится внутри единственной ссылки на внутреннюю страницу кейса. Пользователь ожидает внешний переход, но открывает описание проекта.
- Страницы проектов дают краткое описание и список возможностей. На TaskFocus нет скриншота; у кейсов нет рассказа о проблеме, личной роли, ограничениях, ключевых решениях и подтверждённом результате.

### P2 — Слабая связь с целью поиска работы

- В About нет конкретной профессиональной истории; Contact предлагает «создать что-то полезное» и «обсудить продукт или проект», а не обсуждать роль или вакансию.
- На странице не видно резюме или LinkedIn. Добавлять ссылки следует только при наличии актуальных и подтверждённых материалов.
- Английский язык задан по умолчанию в `index.html` и `context.tsx`, а заголовок вкладки остаётся английским после переключения интерфейса на русский. Основной рынок ещё не выбран.
- Палитра команд Ctrl+K добавляет интерфейсную сложность, хотя сайт содержит только несколько разделов и проектов. Стоит проверить, помогает ли она рекрутеру.

### P2 — Небольшие технические замечания

- Страницы с изображением проекта вызывают предупреждение React о свойстве `fetchPriority` на `<img>` (`CaseStudy.tsx`).
- На главной в браузерной консоли есть два предупреждения React Router о будущих изменениях в версии 7. Ошибок загрузки главной и горизонтального переполнения на 320 px не обнаружено.
- Переключение языка и открытие страницы TaskFocus вручную сработали. Скриншотные страницы открываются, их локальные изображения загружаются.

## Reference Patterns

Страница [консультаций Лизы Гусенковой](https://liza-career.ru/consultations) помогает посетителю быстро понять предложение, узнать подходящие ситуации, увидеть процесс, доказательства результата, сведения об авторе и понятный следующий шаг. Для портфолио переносим эти принципы в форму «кому подходит мой профиль → релевантные кейсы → мой вклад и решения → проверяемые материалы → резюме или контакт». Цены, консультационные пакеты и клиентские отзывы к поиску работы не добавляем.
